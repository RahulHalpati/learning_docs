# Section 05 · Async database: SQLAlchemy 2.0 + Alembic

> **Prerequisites:** [04 · Dependency injection & app structure](../04_dependency_injection_app_structure/README.md) · **Time:** ~6 h

An in-memory dict dies with the process. This section gives your service a real data layer: **async SQLAlchemy 2.0** (typed `Mapped[...]` models, the 2.0 query style) talking to **PostgreSQL** over asyncpg, with **Alembic** version-controlling every schema change. You'll wire the engine and per-request sessions, model relationships, master the async loading pitfalls, and learn migration discipline that survives a team and a production deploy.

## Mini-project

Persist **linkbox** (your link-shortener from Section 04) to PostgreSQL — kill the in-memory dict for good.

Run Postgres locally:

```bash
docker run -d --name linkbox-pg \
  -e POSTGRES_USER=linkbox -e POSTGRES_PASSWORD=linkbox -e POSTGRES_DB=linkbox \
  -p 5432:5432 postgres:16
```

Then set `DATABASE_URL=postgresql+asyncpg://linkbox:linkbox@localhost:5432/linkbox` in `.env` and `uv add sqlalchemy asyncpg alembic`.

**Requirements checklist:**

- [ ] `Link` model: `id`, unique indexed `slug`, `url`, timestamps (via the mixin from 05-2).
- [ ] `ClickEvent` model: `id`, `link_id` FK, `clicked_at`, optional `referrer` — **one-to-many** from `Link.clicks` with `back_populates` and delete cascade.
- [ ] The in-memory store module replaced by a DB-backed module; endpoints get their session through the `get_db` yield dependency (`DbSession` alias) — no endpoint creates its own session, no `commit()` outside the dependency.
- [ ] Pydantic v2 response schemas with `model_config = ConfigDict(from_attributes=True)`.
- [ ] `alembic init -t async`, `env.py` wired to your settings + metadata; **initial migration** autogenerated, reviewed, and applied.
- [ ] A **second autogenerated migration** adding `expires_at: datetime | None` to `links` — diff reviewed before applying.
- [ ] `GET /links/{slug}/clicks` returns a link's click events with **no lazy-load errors** (explicit `selectinload`).
- [ ] `alembic downgrade base` then `alembic upgrade head` runs clean — your history replays from scratch.

## Test task (gate)

Complete both parts before starting Section 06. Seed your DB first: insert at least 4 links where two pairs share the same slug (drop the unique constraint locally or seed before the initial migration's constraint — the point is duplicates exist).

**Part A — hand-written migration with a data step.** Write a migration **by hand** (`alembic revision`, no `--autogenerate`) that adds a unique constraint on `links.slug`. Adding the constraint on a table with duplicates fails — so the migration must first **dedupe**: a data-migration step (via `op.execute()` / `op.get_bind()`) that rewrites duplicate slugs (e.g. suffix `-2`, `-3`) before `op.create_unique_constraint()`. Write a working `downgrade()` that drops the constraint (the renamed slugs stay — document why data steps are often one-way).

**Part B — the seeded bug.** Add this endpoint as-is, run it, and watch it fail:

```python
@router.get("/links/{slug}/report")
async def link_report(slug: str, db: DbSession):
    result = await db.execute(select(Link).where(Link.slug == slug))
    link = result.scalar_one_or_none()
    return {"slug": link.slug, "clicks": [c.clicked_at for c in link.clicks]}
```

It raises `MissingGreenlet`. In a short written answer, explain **why** async lazy loading fails here (what lazy access needs, and why it can't have it), then fix the endpoint with `selectinload`.

**Passing =** on a database seeded with duplicate slugs, `alembic upgrade head` **and** `alembic downgrade -1` both run clean (upgrade dedupes then constrains; downgrade restores the schema), **and** the report endpoint returns click data with no `MissingGreenlet` / lazy-load error, with a correct one-paragraph explanation of the failure.

## What you'll be able to do after this section

- Configure an async engine (pooling, pre-ping) and give every request an atomic session via `get_db`.
- Model tables and relationships in typed SQLAlchemy 2.0 style, including many-to-many and timestamp mixins.
- Diagnose and prevent `MissingGreenlet` by loading relationships explicitly (`selectinload` / `joinedload`).
- Read, write, paginate (offset **and** keyset), and upsert with the 2.0 query API.
- Evolve a production schema with reviewed Alembic migrations, including hand-written data migrations with working downgrades.
