# 02-1 · S3 (object storage)

> **Level:** Beginner · **Prerequisites:** [01-3 Endpoints & credentials](../01_foundations/03_endpoints_and_credentials.md)
> **Time:** 25 min · **Verified:** 2026-07-16 (LocalStack 3.8.1)

**S3** stores **objects** (files) in **buckets**. It's the workhorse of AWS storage
— backups, uploads, static assets, data lakes. In the capstone it holds link
backups.

---

## Concepts

- **Bucket** — a globally-named container (on real AWS the name is globally unique;
  on LocalStack, just unique to you).
- **Object** — a file plus metadata, addressed by a **key** (e.g. `links/abc.txt`).
- **Key prefixes** act like folders (`links/`) but S3 is really flat.

---

## With `awslocal`

```bash
awslocal s3 mb s3://linkstash-backups                 # make bucket
echo "https://example.com" > abc.txt
awslocal s3 cp abc.txt s3://linkstash-backups/links/abc.txt
awslocal s3 ls s3://linkstash-backups/
```

Verified:

```
$ awslocal s3 cp hello.txt s3://linkstash-backups/demo.txt
upload: ./hello.txt to s3://linkstash-backups/demo.txt
$ awslocal s3 ls s3://linkstash-backups/
                           PRE links/
2026-07-16 15:27:39          6 demo.txt
```

## With boto3

The capstone's backup method ([`app/storage.py`](../99_project_linkstash_cloud/app/storage.py)):

```python
s3 = boto3.client("s3", endpoint_url=os.environ.get("AWS_ENDPOINT_URL") or None)

def backup(self, slug, url):
    key = f"links/{slug}.txt"
    self.s3.put_object(Bucket="linkstash-backups", Key=key, Body=url.encode())
    return key
```

The verified demo run produced `backup: s3 key links/abc123.txt` — a real
`put_object` against LocalStack.

Common operations:

```python
s3.put_object(Bucket=b, Key=k, Body=b"data")     # upload
obj = s3.get_object(Bucket=b, Key=k)["Body"].read()  # download
s3.list_objects_v2(Bucket=b, Prefix="links/")    # list
s3.delete_object(Bucket=b, Key=k)                 # delete
```

---

## `s3_use_path_style` — the LocalStack S3 quirk

Real S3 uses *virtual-hosted* URLs (`bucket.s3.amazonaws.com`). LocalStack prefers
*path-style* (`localhost:4566/bucket`). That's why the OpenTofu provider sets
`s3_use_path_style = true` and boto3 usually handles it automatically. If S3 calls
fail with DNS/host errors against LocalStack, path-style is the fix.

## Recap & next

- ✅ **S3 = objects in buckets**, addressed by a **key**; prefixes fake folders.
- ✅ `awslocal s3 mb/cp/ls` for quick work; **`put_object`/`get_object`** in boto3
  (verified in the capstone backup).
- ✅ Use **path-style** (`s3_use_path_style`) with LocalStack S3.
