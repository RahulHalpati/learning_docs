# 01-1 · Tooling: uv & project setup

> **Level:** Beginner · **Prerequisites:** [00 · Introduction](../00_introduction.md)
> **Time:** ~40 min · **Verified:** 2026-08-07 (Python 3.12 · uv · ruff)

## Why this matters

"Works on my machine" is the oldest failure mode in backend work: a service passes locally, then breaks in CI or production because a teammate's environment has a different Python or a different dependency version. Modern Python fixes this with **uv** (one tool for Python versions, virtualenvs, dependencies, and a lockfile) and **ruff** (one tool for lint and format). Get this right once and every project after it starts in a known-good state — reproducible for you, your team, and CI.

---

## Python 3.12+ — let uv manage it

Don't fight your OS package manager. uv downloads and manages Python interpreters itself:

```bash
# Install uv (one-time; see docs.astral.sh/uv for your platform)
curl -LsSf https://astral.sh/uv/install.sh | sh

uv python install 3.12     # fetch an interpreter — no sudo, no apt/brew
uv python list             # see what's available/installed
```

Why 3.12 as the floor? The typing syntax this course relies on (`X | None`, built-in generics like `list[str]`) is native and idiomatic there, and every library in the 2026 FastAPI stack targets it. Pinning a *minimum* Python per project (you'll see where in a moment) means CI fails loudly on the wrong interpreter instead of failing weirdly at runtime.

## uv: init, add, sync, run, lock

The whole daily workflow is five commands:

```bash
uv init link-checker        # scaffold: pyproject.toml, .python-version, ...
cd link-checker

uv add httpx                # add a runtime dependency
uv add --dev ruff           # add a dev-only dependency (lint/format/test tools)

uv sync                     # make .venv match pyproject + uv.lock exactly
uv run python main.py       # run inside the project env — no manual activation
uv lock                     # (re)resolve and write uv.lock
```

Two habits worth building on day one:

- **Never `pip install` into a uv project.** `uv add` updates `pyproject.toml` *and* the lockfile in one step; a stray pip install updates neither, and the drift bites whoever clones the repo next.
- **Prefix everything with `uv run`.** `uv run pytest`, `uv run ruff check .` — it guarantees the command runs in the project's env, so "did you activate the venv?" stops being a question. CI uses the exact same commands.

---

## pyproject.toml anatomy

One file declares the whole project. A minimal, realistic one:

```toml
[project]
name = "link-checker"
version = "0.1.0"
description = "Concurrent link checker CLI"
requires-python = ">=3.12"          # the floor — uv & CI enforce it
dependencies = [
    "httpx>=0.28",                  # runtime deps: what the app imports
]

[dependency-groups]
dev = [
    "ruff>=0.12",                   # tooling: needed to develop, not to run
]

[tool.ruff]                          # tool config lives here too — one file
line-length = 100
```

- **`requires-python`** — the contract with every environment. Wrong interpreter → immediate, clear error.
- **`dependencies` vs `dev` group** — production images install only `dependencies`; keeping ruff/pytest out of them means smaller images and a smaller attack surface.
- **Version bounds** — `>=` floors in `pyproject.toml`; the *exact* pins live in the lockfile, which is the next topic.

---

## Why lockfiles matter

`pyproject.toml` says `httpx>=0.28` — a *range*. `uv.lock` records the **exact** resolved version of httpx *and every transitive dependency underneath it*, with hashes. That's the difference between "roughly the same environment" and "byte-for-byte the same environment".

```bash
uv sync --locked    # CI: install exactly the lockfile, fail if it's stale
```

- **Commit `uv.lock`** for applications, always. A teammate's `uv sync` then produces your environment, not an approximation of it.
- **Failure mode it prevents:** a transitive dependency ships a subtly breaking release on Tuesday; without a lockfile, Wednesday's CI run installs it and a test fails on code nobody touched. With a lockfile, nothing changes until *you* run `uv lock` — upgrades become a deliberate, reviewable diff.
- **Never commit `.venv/`** — it's a disposable build product regenerated by `uv sync`. The lockfile is the source of truth; the venv is cache.

## ruff: lint + format, one tool

ruff replaces the old flake8 + isort + black pile with two subcommands:

```bash
uv run ruff check . --fix    # lint (and auto-fix what's safe)
uv run ruff format .         # format — the black-style "no arguments" formatter
```

Configuration goes in `pyproject.toml` — same file as everything else:

```toml
[tool.ruff]
line-length = 100
target-version = "py312"     # lets ruff suggest 3.12-idiomatic fixes

[tool.ruff.lint]
select = [
    "E", "F",                # pycodestyle + pyflakes: the baseline
    "I",                     # import sorting (replaces isort)
    "UP",                    # pyupgrade: flags Optional[X] → X | None, etc.
    "B",                     # bugbear: real bug patterns, e.g. mutable defaults
]
```

The **`UP`** rules are why ruff belongs in this section: they mechanically enforce the modern typing style the rest of the course requires. Write `Optional[str]` and ruff rewrites it to `str | None` for you. Formatting is deliberately not configurable beyond line length — nothing to argue about in review, which is the point.

## src layout vs flat

Two ways to arrange the code:

```text
flat                          src layout
────                          ──────────
link-checker/                 link-checker/
├── pyproject.toml            ├── pyproject.toml
├── main.py                   └── src/
└── checker.py                    └── link_checker/
                                       ├── __init__.py
                                       └── checker.py
```

- **Flat** — fine for scripts and this section's mini-project. Zero ceremony.
- **src layout** — the standard for anything installable or long-lived, and what this course's project sections use. The why: with flat layout, `import checker` can silently resolve to the *file in your working directory* instead of the installed package — so tests pass locally against code that was never packaged, then break for everyone else. `src/` makes that accident impossible: the package is only importable once properly installed into the env.

Rule of thumb: one-file tool → flat; anything with tests and a package name → src.

## Recap & next

- ✅ uv is the one tool: `uv python install` for interpreters, `uv init` / `uv add` / `uv sync` / `uv run` / `uv lock` for everything else.
- ✅ `pyproject.toml` declares ranges and config; **`uv.lock` pins exact versions** — commit it, and `uv sync --locked` in CI makes environments reproducible.
- ✅ ruff does lint *and* format; the `UP` rules enforce modern typing syntax automatically.
- ✅ Flat layout for scripts, **src layout** for real packages — src prevents "imported the local file, not the installed package" bugs.
- ✅ Self-check: your teammate clones the repo and runs `uv sync`. Which two files fully determine what lands in their `.venv`?

## Exercises

1. Create a project with `uv init hello-uv`, add httpx as a runtime dep and ruff as a dev dep, and run `uv run python -c "import httpx; print(httpx.__version__)"`. Then open `uv.lock` and count how many packages got locked for that *one* direct dependency.

<details>
<summary>Solution</summary>

```bash
uv init hello-uv && cd hello-uv
uv add httpx
uv add --dev ruff
uv run python -c "import httpx; print(httpx.__version__)"
```

`uv.lock` will list httpx plus its transitive deps (httpcore, anyio, idna, certifi, h11, sniffio...). That's the point of the lockfile: those ~7 indirect versions are pinned too, even though you never named them.
</details>

2. Add the ruff config from this lesson to `pyproject.toml`, then write a file containing `from typing import Optional` and a function returning `Optional[str]`. Run `uv run ruff check . --fix`. What happens, and which rule group did it?

<details>
<summary>Solution</summary>

Ruff rewrites the annotation to `str | None` and removes the now-unused `Optional` import. That's the `UP` (pyupgrade) rules — with `target-version = "py312"` ruff knows the `X | None` syntax is available and enforces it. The old style now literally cannot survive a lint run.
</details>

3. Delete your project's `.venv` directory entirely, then run `uv sync`. Why is this safe — and what *would* have been lost if you'd committed `.venv` and ignored `uv.lock` instead?

<details>
<summary>Solution</summary>

`uv sync` rebuilds `.venv` exactly from `uv.lock` in seconds — the venv is a disposable artifact. The reverse setup is backwards: a committed `.venv` is platform-specific (Linux wheels won't run on a teammate's Mac) and bloats the repo, while the missing lockfile means nobody can reproduce the resolution that produced it.
</details>
