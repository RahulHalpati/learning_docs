# 03-1 · S3 (object storage)

> **Level:** Beginner · **Prerequisites:** [01-3 Endpoints & credentials](../01_foundations/03_endpoints_and_credentials.md)
> **Time:** 30 min · **Verified:** 2026-07-16 (LocalStack 3.8.1; runs unchanged on Floci) — event notifications to SQS re-verified 2026-09-01

**S3** stores **objects** (files) in **buckets**. It's the workhorse of AWS storage
— backups, uploads, static assets, data lakes. In the capstone it holds link
backups.

---

## Concepts

- **Bucket** — a globally-named container (on real AWS the name is globally unique;
  on Floci, just unique to you).
- **Object** — a file plus metadata, addressed by a **key** (e.g. `links/abc.txt`).
- **Key prefixes** act like folders (`links/`) but S3 is really flat.

---

## With `awslocal`

```bash
awslocal s3 mb s3://linkstash-backups                 # make bucket
echo "https://example.com" > abc.txt
awslocal s3 cp abc.txt s3://linkstash-backups/links/abc.txt
awslocal s3 ls s3://linkstash-backups/
```

Verified:

```
$ awslocal s3 cp hello.txt s3://linkstash-backups/demo.txt
upload: ./hello.txt to s3://linkstash-backups/demo.txt
$ awslocal s3 ls s3://linkstash-backups/
                           PRE links/
2026-07-16 15:27:39          6 demo.txt
```

## With boto3

The capstone's backup method ([`app/storage.py`](../99_project_linkstash_cloud/app/storage.py)):

```python
s3 = boto3.client("s3", endpoint_url=os.environ.get("AWS_ENDPOINT_URL") or None)

def backup(self, slug, url):
    key = f"links/{slug}.txt"
    self.s3.put_object(Bucket="linkstash-backups", Key=key, Body=url.encode())
    return key
```

The verified demo run produced `backup: s3 key links/abc123.txt` — a real
`put_object` against Floci.

Common operations:

```python
s3.put_object(Bucket=b, Key=k, Body=b"data")     # upload
obj = s3.get_object(Bucket=b, Key=k)["Body"].read()  # download
s3.list_objects_v2(Bucket=b, Prefix="links/")    # list
s3.delete_object(Bucket=b, Key=k)                 # delete
```

## `s3_use_path_style` — the Floci S3 quirk

Real S3 uses *virtual-hosted* URLs (`bucket.s3.amazonaws.com`). Floci prefers
*path-style* (`localhost:4566/bucket`). That's why the OpenTofu provider sets
`s3_use_path_style = true` and boto3 usually handles it automatically. If S3 calls
fail with DNS/host errors against Floci, path-style is the fix.

## Access: private, downloadable, streamable, restricted

Storing an object is half the job — **who can read it, and how** is the other half.
Objects are **private by default**. The three things you actually reach for:

```python
# 1) Presigned URL — a temporary, credential-free link. THE way to hand a user a
#    download/stream of a private object. Works on Floci.
url = s3.generate_presigned_url(
    "get_object",
    Params={"Bucket": b, "Key": k},
    ExpiresIn=3600,          # link dies in 1 hour
)

# 2) Download vs stream — Content-Disposition + Content-Type decide browser behaviour.
s3.put_object(Bucket=b, Key=k, Body=data,
    ContentType="video/mp4",
    ContentDisposition="inline")      # "inline" = stream in browser; "attachment" = force download

# 3) Restrict / open — a bucket policy (resource-based, see 02-2) or public-access-block.
```

- **Presigned URLs** are the answer to "let this one user download/stream this private
  file for a while" — no bucket exposure, no shared credentials. This actually works on
  Floci.
- **`ContentDisposition`** flips downloadable ↔ streamable; **`ContentType`** lets the
  browser stream media inline.
- **Bucket policies / public-access-block** are how you make a bucket public or lock it
  down — but **Floci doesn't *enforce* IAM/bucket policies** ([02-1](../02_iam_and_access/01_access_model_iam_sts.md)), so author them here and verify the *restriction* on real AWS. Full per-service policies: [02-2](../02_iam_and_access/02_roles_and_policies_per_service.md).

## Making S3 the trigger, not just the target: event notifications

Every S3 use so far has your app *calling* S3. Real systems often run it the
other way: **an upload triggers processing** — a thumbnail generated, a virus
scan, an ingestion pipeline — without your app polling anything.

```bash
QARN=$(awslocal sqs get-queue-attributes --queue-url $QURL --attribute-names QueueArn --query 'Attributes.QueueArn' --output text)
awslocal s3api put-bucket-notification-configuration --bucket linkstash-backups \
  --notification-configuration "{\"QueueConfigurations\":[{\"QueueArn\":\"$QARN\",\"Events\":[\"s3:ObjectCreated:*\"]}]}"
```

Verified: uploading `uploads/f.txt` after wiring this produced a real SQS
message — `{"Records":[{"eventName":"ObjectCreated:Put","s3":{"object":{"key":"uploads/f.txt"}}}]}` —
with no app code polling S3 at all. (On real AWS the queue also needs a
**resource policy** granting `s3.amazonaws.com` permission to send; Floci
didn't require it here since, like every resource policy, it isn't enforced —
add it anyway for code that's going to production.)

This is the actual mechanism behind "upload a file, get a processed result
back" pipelines — S3 → SQS (queue it) or S3 → Lambda (process immediately),
your choice depending on whether you need buffering/retry (queue) or
synchronous-ish processing (direct Lambda trigger,
[06-5](../06_more_services/05_rds.md) territory once a database is involved).

## Two more things a "real app" needs

- **Multipart upload** for anything large (AWS recommends it above ~100MB,
  required above 5GB): split the object into parts, upload them
  (in parallel, with retries *per part* instead of restarting the whole
  file), then complete. `boto3`'s `upload_file()`/`TransferManager` does this
  **automatically** above a size threshold — you rarely call the multipart
  API by hand, but you should know why a huge single `put_object` is the
  wrong tool.
- **Lifecycle policies** move or delete objects automatically by age —
  `transition to STANDARD_IA after 30 days, expire after 365` — so storage
  cost tracks how old/accessed data actually is instead of everything sitting
  at the most expensive tier forever. Configured once on the bucket, zero
  ongoing app code.

## Recap & next

- ✅ **S3 = objects in buckets**, addressed by a **key**; prefixes fake folders.
- ✅ `awslocal s3 mb/cp/ls` for quick work; **`put_object`/`get_object`** in boto3
  (verified in the capstone backup).
- ✅ Use **path-style** (`s3_use_path_style`) with Floci S3.
- ✅ **Access:** private by default; **presigned URLs** to share a download/stream,
  **Content-Disposition** for download-vs-stream, **bucket policies** to restrict
  (authored here, *enforced* only on real AWS).
- ✅ **Event notifications** turn S3 into a trigger (upload → SQS/Lambda), verified
  end to end; **multipart upload** and **lifecycle policies** handle large files
  and aging data with no app code.
