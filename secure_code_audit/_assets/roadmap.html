Static, not dynamic

The sibling of Ethical Hacking

That course attacks a running app (sqlmap, Burp, hydra) and defers code review, SAST, and dependency scanning to "the next course." This is that course — same vulnerabilities, found by reading the source.

source .py→ tokenize→ AST→ pattern rules+ taint→ findings · SARIF

Two ways a scanner sees a bug

Patterns you flag on sight · flows you must trace

The whole reason the course has both a rules engine and a taint tracker.

Pattern rules

Dangerous regardless of input — flag on sight.
eval() · md5() · debug=True · hardcoded key

Taint tracking

Dangerous only if user data reaches it — follow the flow, source → sink.
request.args → open() / execute() / requests.get()

Same target, three tools

No single tool is a superset

Run on the bundled vulnerable app — real numbers from the verified environment. This is why teams run several, and why building one teaches you to read them all.

codeaudit (yours)14taint: input → open/execute/httpsmall rule set; intraprocedural

Prove it in 60 seconds

Quick start

# in 99_project_codeaudit/ — the auditor needs no third-party packages
python -m codeaudit.cli samples/vulnerable_app
python -m codeaudit.cli samples/vulnerable_app --format sarif      # for CI
python -m codeaudit.cli samples/vulnerable_app --deps samples/vulnerable_app/requirements.txt
python -m pytest -q                                            # 16 passed

Ethics: the bundled app is intentionally vulnerable — a practice target only. Audit only code you own or are authorised to review, and disclose real third-party findings responsibly.
