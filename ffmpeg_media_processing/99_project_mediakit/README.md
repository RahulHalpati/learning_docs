The toolkit this course builds. Every function is one lesson's worth of ffmpeg knowledge, wrapped so your application never builds a command line by hand.

It's **stdlib-only** — ffmpeg does the work, so there's nothing to install but pytest.

## Run it

```bash
sudo apt install ffmpeg          # or: brew install ffmpeg
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt  # just pytest
pytest -q
```

**Output (real run):**
```
.......................                                                  [100%]
23 passed in 8.14s
```

The tests use **real ffmpeg on real files** — no mocks. A mocked subprocess would prove the Python is consistent while proving nothing about whether the commands work, which is the only thing that matters here. The sample video is generated by ffmpeg at test time (`tests/conftest.py`), so there are no binary blobs in the repo and the media is identical on every machine.

## Design notes

**Why the offline fallback.** Without faster-whisper installed, `transcribe()` returns cues with *real timings* from silence detection and placeholder text. The cut/reframe/caption path stays fully testable in CI, in seconds, on a machine with no models — the same "deterministic stub for the expensive probabilistic part" pattern as the [LLM Evals](../../llm_evals_observability/) course.

**Why three encodes in `make_clip`.** Cut → reframe → caption writes an inspectable intermediate at each step, which is worth a lot while learning. It also costs three generations of quality loss ([02-1](../02_core_operations/01_converting.md)). Chaining the filters into one command is the first optimisation to make — see the exercise in [04-2](../04_subtitles/02_burning_captions.md).

**Why `pick_highlight` is naive.** It picks the densest window of speech. It's a placeholder with a clear interface, and swapping it for an LLM call is the change that makes this an AI product ([06-4](../06_python_automation/04_transcription.md)).

## Make it your portfolio piece

The toolkit is deliberately a foundation, not a finished product. Real upgrades, roughly in order of value:

1. **Swap `pick_highlight` for an LLM** — hand it the transcript, ask for the most engaging span. This is the smallest change with the biggest story.
2. **Subject-tracked cropping.** The centre crop assumes the speaker is centred ([03-2](../03_filters/02_scale_crop_vertical.md)). Detect faces per frame, smooth the path, drive the crop's X from it. PyAV gives you frame access without shelling out ([06-1](../06_python_automation/01_subprocess_basics.md)).
3. **Single-command rendering** — one decode, one encode, ~3× faster and visibly better.
4. **Word-level captions** with `word_timestamps=True` and ASS styling — the animated look short-form audiences expect.
5. **Wrap it in an API** with a job queue ([Production FastAPI Backend](../../fastapi_production_backend/)) — upload, poll, download.
6. **Measure the highlight picker** against human-chosen clips ([LLM Evals](../../llm_evals_observability/)). *"My clip selector agrees with human picks 71% of the time"* is a far stronger claim than *"it uses AI"*.

That last point generalises: the media layer here is deterministic and tested, so when something in the product is wrong you can tell whether it's the ffmpeg or the model. Most video-AI demos can't.
