# Section 09 · Docs & developer experience

> **Prerequisites:** The finished, published SDK ([Section 99](../99_project_pokesdk/README.md) + [Section 08](../08_packaging_publishing/README.md)).
> **Time:** ~1–2 hours.

Your SDK works, it's typed, tested, and on PyPI. But adoption hinges on something the code alone can't deliver: **can a stranger get from `pip install` to a working call in two minutes?** This short final section covers the docs and ergonomics that decide that — the README that is the first (and often only) thing people read, docstrings that power editor help, runnable examples, and the small DX touches that make an SDK feel professional rather than homemade.

## What you'll be able to do after this section

- Write a README that gets a user to a working call fast (install → quickstart → common tasks).
- Write docstrings that show up usefully in editors and doc generators.
- Ship runnable examples and a clear errors/auth/async guide.
- Apply the small DX touches (good `repr`, helpful error messages, consistent naming) that signal quality.
